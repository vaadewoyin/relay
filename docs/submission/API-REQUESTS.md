# Optional API feature requests

1. **Even Hub Simulator · WSLg input routing diagnostics.** Expose capture backend, selectable host inputs, selected input, and a PCM level probe, with actionable guidance if the fallback device is silent. The documented audio-device listing, device selection, and PCM event already exist. The Relay Phase 6 simulator build (0.7.3 on WSLg) listed only `alsa:null`, so speech capture remained unverified in that environment. A routing diagnostic would separate host input problems from SDK delivery problems. [Observed voice gate](../VOICE.md) · [Simulator audio documentation](https://hub.evenrealities.com/docs/test/simulator#options)
2. **Even Hub Simulator · observable exit confirmation outcome.** Expose a simulator-only automation event or state giving the system exit-confirmation visibility, selected choice, and outcome, with a deterministic test path to cancel or exit. The documented double-click input can drive the root exit flow and framebuffer screenshots can be inspected. Relay's earlier simulator run received the input but could not verify the system dialog outcome. A first-class result would make regression assertions independent of screenshot heuristics and clarify differences between builds. [Simulator automation](https://hub.evenrealities.com/docs/test/simulator#headless-automation-v070) · [Observed limitation](../../frontend/DESIGN.md)
3. **Notion · conditional page updates.** Let callers pass an expected page revision or ETag with a properties update, returning a conflict on revision mismatch. The documented page PATCH has no conditional write precondition. Relay checks the current owner and last-edited revision before PATCH, which still leaves a read/write race against a concurrent external change. A server-side precondition would protect operator edits at the write itself. [Notion update page](https://developers.notion.com/reference/patch-page) · [Relay sync behavior](../../backend/README.md#repeatable-startup)
